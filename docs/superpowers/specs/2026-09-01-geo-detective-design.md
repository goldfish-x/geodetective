# 《地理大侦探》设计与架构文档（v0.2）

> 更新记录：2026-09-23 —— 同步当前代码实现：游戏改为 **10 局 × 8 题**；补充局门槛、地名档案、程序化音效、路由级代码分割、本地存档边界与测试规范。旧文档中“一局 10 题、每局两个道具”等描述已废弃。

## 1. 游戏概述

| 项目 | 内容 |
| --- | --- |
| 游戏名 | 地理大侦探 |
| 类型 | 地理竞猜 · 关卡制休闲竞技 |
| 平台 | 响应式 Web，桌面与移动浏览器 |
| 一句话简介 | 系统给出地名档案，玩家在地图或 3D 地球上点击其真实位置，越准得分越高 |
| 局制 | 10 局 × 8 题，最多 80 题 |
| 单题满分 | 5000 分 |
| 理论满分 | 400000 分 |
| 存档 | 本地 localStorage，无后端 |

## 2. 游戏模式

### 2.1 中国篇

- ECharts 2D `geo` 中国省级地图。
- 支持拖拽、缩放、触控。
- 点击通过像素转经纬度实现，按下与抬起位移小于 6px 才视为点击，避免拖拽误判。
- 中国境外点击会被拒绝。
- 每题限时 **15 秒**。

### 2.2 世界篇

- ECharts GL 3D 地球。
- 世界地图先渲染到 2048×1024 离屏 canvas，作为等距圆柱贴图。
- 必须显式设置 `aspectScale: 1`、`boundingCoords: [[-180, -90], [180, 90]]`、`left/top/width/height`，否则球面 UV 与经纬度会错位。
- 点击通过相机射线与球体求交，再反算经纬度。
- 每题限时 **20 秒**。

## 3. 关卡与题库

当前实现为 **10 局，每局 8 题**：

| 局 | 类型 | 难度 | 通关门槛 |
| --- | --- | ---: | ---: |
| 1 | 城市 | 1 简单 | 8000 |
| 2 | 景点 | 1 简单 | 9000 |
| 3 | 城市 | 2 普通 | 10000 |
| 4 | 景点 | 2 普通 | 11000 |
| 5 | 城市 | 3 进阶 | 12000 |
| 6 | 景点 | 3 进阶 | 13000 |
| 7 | 城市 | 4 困难 | 14000 |
| 8 | 景点 | 4 困难 | 15000 |
| 9 | 城市 | 5 地狱 | 16000 |
| 10 | 景点 | 5 地狱 | 17000 |

规则：

- 城市局与景点局交替。
- 每局 8 题均为同一类型与难度。
- 一次游戏的 80 题尽量不重复。
- 局末得分低于门槛则任务中止；达标进入下一局。
- 最后一局达标则完美结案。

### 题库规模

每个模式均为：

- 150 个城市。
- 150 个景点。
- 每类难度 1–5 各 30 题。
- 合计 300 题。

题库结构：

```json
{
  "name": "敦煌莫高窟",
  "lat": 40.0424,
  "lng": 94.8096,
  "difficulty": 2,
  "hint": "西北地区"
}
```

中国题的 `hint` 为大区；世界题的 `hint` 为大洲。

### 地名档案

`china-desc.json` 与 `world-desc.json` 各 300 条，键为题名：

```json
{
  "敦煌莫高窟": {
    "desc": "地点简介……",
    "img": "配图生成 prompt……"
  }
}
```

- 每条包含 100–200 字简介。
- 难度 1–2 的地点有配图 prompt，通过远程图片接口生成。
- 难度 3–5 不配图，避免接口压力并突出文字档案。

## 4. 计分与计时

### 距离

使用 Haversine 球面距离，地球半径取 6371 km。

### 公式

```text
得分 = 5000 × (1 − (distance / maxDistance) ^ decayK)
```

| 模式 | 距离上限 | 衰减指数 | 每题时间 |
| --- | ---: | ---: | ---: |
| 中国篇 | 300 km | 1.7 | 15 秒 |
| 世界篇 | 1500 km | 2.3 | 20 秒 |

- 超出距离上限为 0 分。
- 超时或未指认为 0 分。
- 时间不参与加分。
- 倒计时最后 3 秒有滴答音与文本脉冲。

## 5. 道具

每一局开始时重置两个道具，均为本局一次：

| 道具 | 效果 |
| --- | --- |
| ⏳ 加时沙漏 | 当前题剩余时间 +10 秒 |
| 🧭 侦探指南 | 中国篇显示大区并高亮省份；世界篇显示大洲文字 |

世界篇的大洲高亮暂未实现，是当前原型限制。

## 6. 游戏状态机

```text
ANSWERING
  ├─ 玩家点击 → 显示确认弹层 → 可重选或确认
  │    └─ CONFIRM_SETTLE → 计算距离/得分 → 揭示答案与连线
  └─ 时间归零 → TIMEOUT_SETTLE → 0 分
       ↓
SETTLE
  ↓ 2.5 秒自动下一题，或点击“下一题”
NEXT_QUESTION
  ├─ 未满 8 题 → ANSWERING
  └─ 已满 8 题 → STAGE_SETTLE
STAGE_SETTLE
  ├─ 未达标 → RESULT(failed)
  ├─ 非最后一局达标 → 下一局 ANSWERING
  └─ 最后一局达标 → RESULT(victory)
```

## 7. 结算设计

### 单题结算

- 显示判级：精准 / 接近 / 偏远 / 失手 / 超时。
- 显示本题得分。
- 显示题名、难度、与实际位置的距离。
- 新增精准度刻度条，按得分比例填充并变色。
- 地图上显示玩家点、答案点与连线。
- 弹层 2.5 秒后自动进入下一题，也可手动跳过。

### 局结算

- 显示本局得分与通关门槛。
- 列出本局 8 个地名。
- 悬停或点击地名显示简介、坐标、配图与地图红点。
- 世界篇会自动把镜头转向该地点。
- 通过显示“通关”，失败显示“未达标”。

### 终局结算

- 显示任务状态：完美结案 / 任务中止。
- 显示总分与止步局数。
- 显示 10 局进度点。
- 显示最多 80 行逐题回顾。
- 写入本机 Top 10 榜单。

## 8. 存储与多人比较边界

### 当前本地存档

| Key | 内容 |
| --- | --- |
| `gd_nickname` | 玩家昵称 |
| `gd_leaderboard` | 中国篇与世界篇各自 Top 10 |
| `gd-muted` | 音效开关 |

localStorage 的特点：

- 成绩在**同一浏览器、同一设备**中可持久保存。
- 清理浏览器数据、换浏览器、换设备后不会自动同步。
- 不同玩家如果使用同一浏览器同一站点，会看到同一个本地榜单，无法真正区分账号。
- 没有后端时，不能提供可靠的跨设备成绩、多人实时排行、防作弊或好友比较。

### 若需要真正多人比较

可后续增加后端或 Serverless API，最少需要：

- 玩家身份。
- 成绩提交接口。
- 排行榜查询接口。
- 基础合法性校验与限流。
- 数据库或 KV 存储。

## 9. 技术架构

```text
index.html
└── src/main.js                  # hash 路由与资源清理
    ├── ui/home.js               # 首页、昵称、模式、排行榜
    └── ui/game.js               # 游戏状态机与结算
        ├── core/quiz.js         # 关卡与抽题
        ├── core/scoring.js      # Haversine 与得分
        ├── core/storage.js      # localStorage
        ├── core/audio.js        # WebAudio 程序化音效
        ├── ui/map-china.js       # 中国 2D 地图（懒加载）
        └── ui/map-world.js       # 世界 3D 地球（懒加载）
```

### 构建与包体

- Vite 构建。
- ECharts、ECharts GL、地图 GeoJSON、题库按模式懒加载。
- 首页不加载 3D 地球或中国地图，降低首屏 JS 体积。
- 生产构建仍会生成较大的地图/题库 chunk，这是数据型应用的正常代价；后续可继续做 GeoJSON 简化或服务端数据源。

### 音效

- 无音频文件。
- Web Audio API 程序化合成。
- 首次用户交互后解锁 AudioContext。
- 支持静音并持久化偏好。

## 10. 测试规范

- Python Playwright 回归脚本位于 `tests/`。
- 所有脚本使用 `Path(__file__).resolve().parents[1]` 推导项目根目录，禁止硬编码个人绝对路径。
- 测试地址默认 `http://127.0.0.1:5173`，可用环境变量 `GD_BASE` 覆盖。
- 启动方式：

```bash
npm run dev
# 另开终端
GD_BASE=http://127.0.0.1:5173 .venv/Scripts/python.exe tests/full_game.py
```

- 生成的 PNG 截图为本地测试产物，默认不纳入 Git。
- `window.__gdDebug` 仅供自动化测试读取内部状态。
- `window.__gdCleanup` 负责路由切换时清理计时器、动画与地图实例。
