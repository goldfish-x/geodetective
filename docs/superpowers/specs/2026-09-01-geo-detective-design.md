## 1. 游戏概述

| 项目 | 内容 |
| --- | --- |
| 游戏名 | 地理大侦探 |
| 类型 | 地理竞猜 · 关卡制休闲竞技 |
| 平台 | 响应式 Web，桌面与移动浏览器 |
| 一句话简介 | 系统给出地名档案，玩家在地图或 3D 地球上点击其真实位置，越准得分越高 |
| 局制 | 10 局 × 8 题，最多 80 题 |
| 单题满分 | 5000 分 |
| 理论满分 | 400000 分 |
| 存档 | 本地 localStorage，无后端 |

## 2. 游戏模式

### 2.1 中国篇

- ECharts 2D `geo` 中国省级地图。
- 支持拖拽、缩放、触控。
- 点击通过像素转经纬度实现，按下与抬起位移小于 6px 才视为点击，避免拖拽误判。
- 中国境外点击会被拒绝。
- 每题限时 **15 秒**。

### 2.2 世界篇

- ECharts GL 3D 地球。
- 世界地图先渲染到 2048×1024 离屏 canvas，作为等距圆柱贴图。
- 必须显式设置 `aspectScale: 1`、`boundingCoords: [[-180, -90], [180, 90]]`、`left/top/width/height`，否则球面 UV 与经纬度会错位。
- 点击通过相机射线与球体求交，再反算经纬度。
- 每题限时 **20 秒**。

## 3. 关卡与题库

当前实现为 **10 局，每局 8 题**：

| 局 | 类型 | 难度 | 通关门槛 |
| --- | --- | ---: | ---: |
| 1 | 城市 | 1 简单 | 8000 |
| 2 | 景点 | 1 简单 | 9000 |
| 3 | 城市 | 2 普通 | 10000 |
| 4 | 景点 | 2 普通 | 11000 |
| 5 | 城市 | 3 进阶 | 12000 |
| 6 | 景点 | 3 进阶 | 13000 |
| 7 | 城市 | 4 困难 | 14000 |
| 8 | 景点 | 4 困难 | 15000 |
| 9 | 城市 | 5 地狱 | 16000 |
| 10 | 景点 | 5 地狱 | 17000 |

规则：

- 城市局与景点局交替。
- 每局 8 题均为同一类型与难度。
- 一次游戏的 80 题尽量不重复。
- 局末得分低于门槛则任务中止；达标进入下一局。
- 最后一局达标则完美结案。

### 题库规模

每个模式均为：

- 200 个城市。
- 200 个景点。
- 每类难度 1–5 各 40 题（即每局的抽题池 40 个，2026-09-30 由 30 扩到 40）。
- 合计 400 题／模式，两篇共 800 题。
- 扩池后每局 8 题仍从同难度池中随机抽取，重复率由 8/30 降到 8/40，连玩多局的题面重合度明显下降。

题库结构：

```json
{
  "name": "敦煌莫高窟",
  "lat": 40.0424,
  "lng": 94.8096,
  "difficulty": 2,
  "hint": "西北地区"
}
```

中国题的 `hint` 为大区；世界题的 `hint` 为大洲。

### 地名档案

`china-desc.json` 与 `world-desc.json` 各 300 条，键为题名：

```json
{
  "敦煌莫高窟": {
    "desc": "地点简介……",
    "img": "配图生成 prompt……"
  }
}
```

- 每条包含 100–200 字简介。
- `img` 字段是**一二星地点的配图画面描述**（每篇 120 条），既是出图 prompt，也是「图文必须对应」的验收依据；
  三四五星没有 `img`，但同样有图（见下）。
- 配图不依赖任何远程图片接口：全部是本地静态资产 `public/images/<篇章>/<地名>.webp`，
  统一 300×300 WebP、单张 1.5–80 KB，档案面板与结算卡共用同一份。
- 每篇 400 个地名的来源分四类：
  1. **Wikimedia Commons 真拍 462 张**（中国篇三四五星 152 + 世界篇 262 为一二星 83 张，
     另 2026-10-01 用坐标邻近检索把 48 张网络检索图换成了可署名真拍），
     逐张登记在 `scripts/*-provenance.json`，并由 `scripts/generate_attribution.py` 汇总进 `ATTRIBUTION.md` 满足 CC 署名。
  2. **AI 写实渲染 157 张**（中国篇一二星 120 + 世界篇 37），构图与打光和真拍差距明显，
     已连同逐条画面提示词列入 `docs/image-restyle-list.md`，等待换成真拍或重绘。
  3. **网络检索图 149 张**（2026-09-30 扩池新增的 100 个／模式地名，原 197 张中 48 张已换成 Commons 可署名真拍），
     由百度图片接口检索、Qwen-VL 逐张核验「是该地实景」且「为纯实景照片而非海报/拼图/地图」后入库，
     逐条登记在 `scripts/<mode>-image-web-provenance.json`。
     **这批图授权未核验**，商用（付费上线）前必须替换为 CC 真拍或自有拍摄，见第 11 节风险。
     换源流程：`GD_REPLACE=1 GD_STAGE=_ccstage python scripts/fetch_geo_images.py <mode> 9000` 取候选到暂存目录
     （`ggsradius` 上限 10000，传 12000 会静默返回空），再由 Qwen-VL 双条件核验后提升；
     未通过核验的候选一律不覆盖原图，登记里会写明回退原因。
  4. **作者提供 AI 生成图 3 张**（`东方`、`法考托`、`阿卢斯`——搜不到合格实景照片的五星地名，按约定不代生成插图，
     由作者按特征提示词自行出图后交付），登记在 `scripts/image-authored-provenance.json`，无第三方授权风险。
     至此扩池新增的 200 个地名配图全部齐备，每篇 400 张。
  4. **29 张三四五星难点**（中国篇 28 + 世界篇 1）原先由 `scripts/generate_illustrations.py` 画成扁平海报插画；
     2026-09-28 已全部替换为 600×600 写实出图（居中裁方 + LANCZOS 缩至 300 + WebP q80，单张 9.6–30.8 KB）。
     出图原档只本地留存于 `assets-src/illustrations-600png/`（已 gitignore），仓库里只有 `.webp`。
     注意：`generate_illustrations.py --force` 会把这些位置重绘回海报风，除统一风格外不要再加 `--force`。

## 4. 计分与计时

### 距离

使用 Haversine 球面距离，地球半径取 6371 km。

### 公式

```text
得分 = 5000 × (1 − (distance / maxDistance) ^ decayK)
```

| 模式 | 距离上限 | 衰减指数 | 每题时间 |
| --- | ---: | ---: | ---: |
| 中国篇 | 300 km | 1.7 | 15 秒 |
| 世界篇 | 1500 km | 2.3 | 20 秒 |

- 超出距离上限为 0 分。
- 超时或未指认为 0 分。
- 时间不参与加分。
- 倒计时最后 3 秒有滴答音与文本脉冲。

## 5. 道具

每一局开始时重置两个道具，均为本局一次：

| 道具 | 效果 | 状态 |
| --- | --- | --- |
| ⏳ 加时沙漏 | 当前题剩余时间 +10 秒 | **已屏蔽**（后续付费内容） |
| 🧭 侦探指南 | 中国篇显示大区并高亮省份；世界篇显示大洲文字 | 开放 |

- 道具开关集中在 `src/ui/game.js` 的 `PROPS` 常量：`{ time: false, hint: true }`。
  关闭时按钮**不渲染进 DOM**（不是隐藏），加时相关的计时与音效逻辑全部保留，
  将来做付费道具时把 `time` 置回 `true` 即可恢复，无需改动流程代码。
- 世界篇的大洲高亮暂未实现，是当前原型限制。

## 6. 游戏状态机

```text
ANSWERING
  ├─ 玩家点击 → 显示确认弹层 → 可重选或确认
  │    └─ CONFIRM_SETTLE → 计算距离/得分 → 揭示答案与连线
  └─ 时间归零 → TIMEOUT_SETTLE → 0 分
       ↓
SETTLE
  ↓ 玩家点击「下一题」（或按回车/空格）
NEXT_QUESTION
  ├─ 未满 8 题 → ANSWERING
  └─ 已满 8 题 → STAGE_SETTLE
STAGE_SETTLE
  ├─ 未达标 → RESULT(failed)
  ├─ 非最后一局达标 → 下一局 ANSWERING
  └─ 最后一局达标 → RESULT(victory)
```

## 7. 结算设计

### 单题结算

- 显示判级：精准 / 接近 / 偏远 / 失手 / 超时。
- 显示本题得分。
- 显示题名、难度、与实际位置的距离。
- 新增精准度刻度条，按得分比例填充并变色。
- 地图上显示玩家点、答案点与连线。
- 弹层保持展开，节奏完全交给玩家：必须点击「下一题」（或按回车/空格）才进入下一题，已取消 2.5 秒自动跳题。
- `startQuestion()` 必须清除上一题的全部揭晓标记（`clearReveal()` + `clearSpot()`）：中国篇的答案点带 `{b}` 地名标签，
  漏清会让下一题一开始就显示上一题的正确位置与名称。
- 结算期间倒计时冻结为「已结算」，避免玩家阅读答案时被时间压力打断。
- 玩家落点与答案点之间的连线统一用浅蓝（#8fd3ff），加粗到 4.5px 以保证在地图上清晰可辨。
- 世界篇的连线是**沿大圆的贴地折线**：自己按球面线性插值（slerp）算出 48 段插值点，配合 `polyline: true` 下发。
  echarts-gl 在 globe 上的 `lines3D` 会忽略 `curveness`、一律用三次贝塞尔拟合，两点夹角一大控制点就被甩到球外，
  表现为连线伸出地球轮廓。
- 连线离地高度由 `globe.globeOuterRadius` 决定：echarts-gl 把高度轴按「数据里的最大 alt」归一化到
  `[0, globeOuterRadius - globeRadius]`，默认 150 会把连线抬到半个球半径之外，因此这里压到 103（离地 3 个单位）。
- 世界篇结算时地球保持玩家当前视角，不再自动回位；只有当答案或落点转到球背面看不见时（与相机朝向夹角 > 66°，
  可见半径 `acos(R/(R+distance)) ≈ 69.5°`），才朝两点的球面中点旋转，近乎对跖时直接面向答案。
- 程序转向必须走 `viewControl.targetCoord`，不能用 `alpha/beta`：echarts-gl 每帧把相机当前角度回写进
  `model.viewControl.alpha/beta`（`globeChangeCamera` action），玩家刚拖拽完地球时该回写会覆盖掉用
  `setOption` 下发的新角度，实测结算转向 0/6 全灭；`targetCoord` 不参与回写且优先级更高。
  代价是它会成为「回位锚点」，所以到位后由 rAF 看守循环摘除，玩家按下鼠标也会立即摘除，避免和人手抢镜头。

### 结算层与地图的布局

结算卡与局档案面板**不浮在地图上**，而是占用一条独立栏位，出现时地图同帧收缩让位，因此任何分辨率下都不会遮住答案红点：

| 视口 | 布局 |
| --- | --- |
| ≥ 900px 宽 | `map-stage` 横向分栏：左 `map-wrap`（自适应）+ 右 `card-slot`（360px 固定列），卡片垂直居中、超高时栏内滚动 |
| < 900px 宽 | `map-stage` 改为纵向：地图在上，卡片作为下方抽屉；面板主操作按钮 `position: sticky` 吸底，保证始终可点 |

- DOM 结构：`map-stage > (map-wrap > map-holder + confirm-pop + toast) + card-slot(id=card-slot) > settle-pop`；局档案面板同样挂进 `card-slot`。
- 显隐由 `game.js` 的 `setSlot(on)` 切换 `card-slot.active`：`startQuestion()` 收起、`settle()` 与 `showStageSettle()` 展开。
- `settle()` 里先 `setSlot(true)` 再 `map.reveal()`，让地图先让位再揭晓，避免红点位置事后跳一下。
- 回归脚本以「卡片包围盒 ∩ 地图包围盒 == 0」为断言，覆盖 1280×800 / 1440×900 / 390×844 / 360×780 × 中国篇/世界篇 × 结算卡/局档案共 16 组，重叠面积均为 0px²。

### 移动端顶栏与提示带

- 顶栏在 ≤560px 下换成两行：第一行「返回 + 局次/本局/总分 + 音效」，第二行「类型徽章 + **待猜地名** + 难度星级」。
  单行布局时 390px 视口下地名只剩 41px 宽，两字以上就被 `text-overflow: ellipsis` 吞掉，玩家看不到题面。
- 地名允许折行（最长 9 字，如「恩戈罗恩戈罗火山口」），字号 `clamp(19px, 5.4vw, 24px)`；
  320/390/430/560px 实测均无横向裁切与右溢。
- 线索横幅由 `absolute + top:62px` 改为文档流提示带：顶栏实测 79~99px，原定位会压在顶栏下沿上。

### 局结算

- 面板停留期间计时条**彻底停车**：宽度归零、文案改为「本局小结」、整条降透明度，
  道具按钮同时置 `disabled`。此前它会留着上一题的 96% 残条并显示「已结算」，
  在窄屏抽屉里看起来就像还在倒计时。
- `tick()` 增加前置守卫：`state.phase !== 'answering'` 直接结束该帧循环，
  任何孤儿 RAF 或后到的回调都不可能再推动计时条。

- 显示本局得分与通关门槛。
- 列出本局 8 个地名。
- 悬停或点击地名显示简介、坐标、配图与地图红点。
- 世界篇会自动把镜头转向该地点。
- 通过显示“通关”，失败显示“未达标”。

### 终局结算

- 显示任务状态：完美结案 / 任务中止。
- 显示总分与止步局数。
- 显示 10 局进度点。
- 显示最多 80 行逐题回顾。
- 写入本机 Top 10 榜单。
- 若本次总分在**该篇章本机榜单里排第一**，追加庆祝画面（见下）。

### 荣誉榜与榜首庆祝

- 荣誉榜前三名：`.bl-idx` 位改为 `1st / 2nd / 3rd` 奖牌胶囊（金 `#e8b64c` / 银 `#cfd8e3` / 铜 `#c67842`），
  整行铺半透明渐变背景板 + 同色内描边，分数同步染色；第 4 名起保持纯序号与虚线分隔，无背景板。
- 登顶判定在 `endGame()` 内：`addScore()` 返回 `rank === 1` 即 `champion`，此时终局卡叠加
  `.result-card.champion`（金色边框 + 内外发光）、`.result-crown`「★ 独占榜首 · 新纪录 ★」、
  `.result-rank.first`「第 1 名 · 本机历史最高」，并落下 36 片金粉雨 `.confetti`。
- 金粉雨是**确定性**生成（LCG 固定种子），每次呈现完全一致，便于自动化断言片数与样式；
  `animation-iteration-count: 3` + `both`，落完三段停在视口外，不会长期残留干扰阅读。
- 庆祝时补一段 `sfxChampion()`（五音上行 + 尾长音 + 三声金粉式高音闪烁），
  延迟 820ms 播放，正好接在印章落稳之后，不与 `sfxVictory` / `sfxGameOver` 叠音。
- 窄屏（≤560px）卡片内宽仅约 300px，王冠行会与右上角印章相撞，故 `margin-top: 38px` 让王冠换到印章下方。
- `prefers-reduced-motion: reduce` 时金粉雨与王冠动画全部关闭（元素仍在，但不落不动）。

## 8. 存储与多人比较边界

### 当前本地存档

| Key | 内容 |
| --- | --- |
| `gd_nickname` | 玩家昵称 |
| `gd_leaderboard` | 中国篇与世界篇各自 Top 10 |
| `gd-muted` | 音效开关 |

localStorage 的特点：

- 成绩在**同一浏览器、同一设备**中可持久保存。
- 清理浏览器数据、换浏览器、换设备后不会自动同步。
- 不同玩家如果使用同一浏览器同一站点，会看到同一个本地榜单，无法真正区分账号。
- 没有后端时，不能提供可靠的跨设备成绩、多人实时排行、防作弊或好友比较。

### 若需要真正多人比较

可后续增加后端或 Serverless API，最少需要：

- 玩家身份。
- 成绩提交接口。
- 排行榜查询接口。
- 基础合法性校验与限流。
- 数据库或 KV 存储。

## 9. 技术架构

```text
index.html
└── src/main.js                  # hash 路由与资源清理
    ├── ui/home.js               # 首页、昵称、模式、排行榜
    └── ui/game.js               # 游戏状态机与结算
        ├── core/quiz.js         # 关卡与抽题
        ├── core/scoring.js      # Haversine 与得分
        ├── core/storage.js      # localStorage
        ├── core/audio.js        # WebAudio 程序化音效
        ├── ui/map-china.js       # 中国 2D 地图（懒加载）
        └── ui/map-world.js       # 世界 3D 地球（懒加载）
```

### 构建与包体

- Vite 构建。
- ECharts、ECharts GL、地图 GeoJSON、题库按模式懒加载。
- 首页不加载 3D 地球或中国地图，降低首屏 JS 体积。
- 生产构建仍会生成较大的地图/题库 chunk，这是数据型应用的正常代价；后续可继续做 GeoJSON 简化或服务端数据源。

### 音效

- 无音频文件。
- Web Audio API 程序化合成（落点 / 确认 / 判级 / 超时 / 告急滴答 / 道具 / 局过关 / 中止 / 全通关 / 登顶凯歌）。
- 首次用户交互后解锁 AudioContext。
- 支持静音并持久化偏好。

## 10. 测试规范

- Python Playwright 回归脚本位于 `tests/`。
- 所有脚本使用 `Path(__file__).resolve().parents[1]` 推导项目根目录，禁止硬编码个人绝对路径。
- 测试地址默认 `http://127.0.0.1:5173`，可用环境变量 `GD_BASE` 覆盖。
- 启动方式：

```bash
npm run dev
# 另开终端
GD_BASE=http://127.0.0.1:5173 .venv/Scripts/python.exe tests/full_game.py
```

- 生成的 PNG 截图为本地测试产物，默认不纳入 Git。
- 布局与镜头专项守卫：
  - `tests/test_layout.py`：16 组「视口 × 篇章 × 结算卡/局档案」断言卡片与地图包围盒重叠面积为 0，并检查主操作按钮在视口内；
    窄屏（≤560px，取 390 与 360 两档）另外注入题库最长地名「恩戈罗恩戈罗火山口」，断言 `#q-name` 不被裁切
